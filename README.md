# SafeStep Backend

The API behind **SafeStep**, an AI-assisted safety-reporting and safety-awareness platform for girls and women who travel alone in Sri Lanka. It is a FastAPI service that accepts incident reports in Sinhala, Tamil, English or mixed text/voice, uses AI to translate and classify them, and turns the eligible reports into privacy-protected map areas and route comparisons.

> Built for **Hack for Humanity — Best Social Impact Web Platform** (Hacktoberfest Hack Day Colombo, organised by AI Collective Colombo with MLH). The repository history starts on 24 October 2026, the day of the hackathon.

## The problem

It is hard to tell whether an unfamiliar road, bus stop or public place is safe for a woman travelling alone. Information about harassment is scattered across social media and private chats, most incidents are never reported, and the people most affected often write in Sinhala, Tamil, or "Singlish" (Sinhala typed in English letters), which generic tools handle poorly. Recurring patterns therefore stay invisible.

## The solution

SafeStep lets people report an incident in their own language, then uses AI to turn free text into structured, comparable data, and shows only **aggregated, privacy-protected** areas on a map. This backend provides:

1. **Reporting.** Authenticated report creation, with English translation of Sinhala / Tamil / Singlish / mixed text and draft voice-to-text.
2. **Incident AI.** An LLM classifies each report (incident type, safety concern, provisional severity 0–10, confidence, lighting, time of day) and flags uncertain ones for human review.
3. **Safety map.** Density-based clustering turns eligible reports into reported-incident areas, never showing individual reports or exact positions.
4. **Journey planner.** Compares routes between two places by how close they pass to reported areas, and can share a live journey with someone you trust.

The service never claims that a place or route is safe. Few reports is reported as "insufficient evidence", not as safety.

## API overview

All routes are under `/api/v1`. "Auth" means a Supabase bearer token (`Authorization: Bearer <access token>`).

| Method and path | Auth | Purpose |
| --- | --- | --- |
| `GET /health` | none | Process health, no external calls |
| `POST /authentication/nic-classification` | token | Parse the gender indicator from a NIC; not identity verification, nothing stored |
| `POST /reports` | token | Create a report; translates if needed, then runs AI analysis |
| `GET /reports` | token | List the caller's own reports (paged) |
| `POST /reporting/transcriptions` | token | Raw audio body to a draft transcript (`language_hint` query) |
| `POST /incident-ai/analyze` | token | Re-run analysis for one of the caller's reports |
| `GET /incident-ai/analyses` | none | Stored analyses, newest first (paged) |
| `GET /safety-map/hotspots` | none | Aggregated areas in a `bbox`, filtered by `time_period` and `window_days` |
| `POST /safety-map/routes/compare` | none | Compare routes between two coordinates (`walking` or `driving`) |
| `GET /safety-map/places` | none | Place suggestions biased to Sri Lanka |
| `POST /journeys` | none | Start a shared journey; returns a share id and an owner key |
| `GET /journeys/{share_id}` | share link | Read a shared journey |
| `PATCH /journeys/{share_id}` | owner key (`X-Journey-Key`) | Update position |
| `DELETE /journeys/{share_id}` | owner key | End and delete the share |

Full request and response contracts are in [docs/api-contracts.md](docs/api-contracts.md) and [docs/safety-map.md](docs/safety-map.md).

## AI usage

AI is central to the product, and each use is bounded and labelled.

| Use | Model / method | Where |
| --- | --- | --- |
| **Translation** of Sinhala, Tamil, Singlish and mixed text to English | `openai/gpt-oss-20b` (open-weight) through the Groq API, strict JSON schema, temperature 0 | `app/modules/reporting/transcription/translation.py` |
| **Incident classification**: incident type, safety concern, severity 0–10, confidence, lighting, time period, immediate-danger flag, neutral summary | `openai/gpt-oss-20b` through Groq, strict JSON schema, temperature 0, versioned prompt (`incident-analysis-v5`) | `app/modules/incident_ai/` |
| **Voice transcription** | `whisper-large-v3` (open-weight) through Groq | `app/modules/reporting/transcription/` |
| **Hotspot detection** | DBSCAN clustering (scikit-learn, haversine metric, 150 m radius, at least 3 reports) | `app/modules/safety_map/hotspots.py` |
| **Route exposure scoring** | Gaussian-kernel proximity to areas, sampled every 25 m | `app/modules/safety_map/routing.py` |

Responsible-AI choices built into the code:

- **Estimates, never verdicts.** The prompt tells the model to treat reports as unverified, never to judge credibility, to ignore instructions embedded in report text, and to separate behaviour that was explicitly reported from a feeling or suspicion. Confidence describes the classification, not whether the incident occurred.
- **Fails safe.** If the model is unavailable or returns invalid output, the analysis is saved as `needs_review` with unknown values instead of a guess. A failed analysis never loses the saved report.
- **Reporter-supplied details win.** Time and lighting entered by the reporter override what the model infers.
- **Needs-review reports are excluded** from the map entirely; low confidence lowers a report's weight but does not drop it.
- **Honest map.** Areas with too few reports are withheld and counted, and an empty result is "insufficient evidence", never "safe".
- **Limits.** Translation and classification can be wrong, especially on Singlish and code-switched text. Hotspots reflect where people *report*, not where harm occurs.

A voice recording is converted, sent to the transcription provider for the request, and never stored; the transcript is only a draft the user confirms.

## Getting started

### Prerequisites

- Python 3.12+
- FFmpeg and ffprobe on `PATH`, only needed for M4A / MP3 transcription (WAV works without them). Ubuntu/Debian: `sudo apt-get install ffmpeg`; macOS: `brew install ffmpeg`; Windows: a build from the [FFmpeg download page](https://ffmpeg.org/download.html).
- Optional, for the full pipeline: a Supabase project and a Groq API key.

### Install

```bash
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
cp .env.example .env               # Windows: Copy-Item .env.example .env
```

### Run

```bash
uvicorn app.main:app --reload
```

- Health: <http://127.0.0.1:8000/api/v1/health>
- Swagger UI: <http://127.0.0.1:8000/docs> (development only)

**You can run it without any credentials.** Health, the NIC parser, hotspots, route comparison and journeys work offline: with no Supabase configuration the safety map serves the synthetic dataset in `sample-data/synthetic_map_reports.json`. The web and mobile apps' map and journey planner work against this. Real report creation, translation, transcription and analysis need the credentials below.

### Configuration

Copy `.env.example` to `.env`. Environment variables take precedence over `.env`. Never commit real values. Service-role and LLM keys belong only on the backend.

| Variable | Needed for |
| --- | --- |
| `APP_ENV` | `development` (default), `test`, `staging`, `production`. Docs and CORS are development only |
| `SUPABASE_URL`, `SUPABASE_JWKS_URL` | Verifying user tokens (`JWKS` is `${SUPABASE_URL}/auth/v1/.well-known/jwks.json`) |
| `SUPABASE_SERVICE_ROLE_KEY` | Backend reads and writes (reports, analyses, map data). Backend only |
| `GROQ_API_KEY` | Translation, classification and transcription |
| `LLM_MODEL`, `LLM_BASE_URL`, `LLM_TIMEOUT_SECONDS` | Override the model and endpoint (defaults: `openai/gpt-oss-20b`, Groq) |
| `TRANSCRIPTION_*` | Optional model, timeouts and limits (limits can only be tightened) |
| `CORS_ALLOW_ORIGINS` | Browser origins allowed in development (defaults to the Vite dev server) |

### Database

Migrations are in `supabase/migrations` and create `reports`, `incident_ai_analyses`, the `map_eligible_incidents` view and the rapid-submission settings and trigger, with RLS enabled and ordinary client access withheld. Apply them to a Supabase project with the Supabase CLI. Optionally load invented demo data with `supabase/seed.sql`, which attaches the rows to an existing auth user. Regenerate the data and seed with `python sample-data/generate_synthetic_reports.py`. See [docs/database.md](docs/database.md).

### Tests and checks

```bash
python -m pytest
python -m ruff check .
python -m ruff format --check .
```

Tests use no credentials and no network. GitHub Actions runs the same checks on every push and pull request, with FFmpeg installed so the audio-conversion tests run rather than skip.

## Privacy and safety

- Report ownership comes only from the verified token subject; the user id is never in a response.
- Ordinary clients have no direct table access; the backend uses a server-side key.
- Public map responses contain only aggregated areas: at least 3 reports, at least 150 m radius, centres rounded to about 110 m, and no text, user ids or exact times.
- Reporter-private context (lighting, current safety status) is not exposed on the map.
- Report text, tokens and audio are never logged. Audio is processed in private temporary files that are removed straight after use.
- Live journey positions are held in process memory only, expire automatically, and are deleted when the traveller ends the journey.
- All demo data is invented. Use fictional data when testing.
- The SOS feature in the apps places a call from the user's own phone. This backend never contacts emergency services.

See [docs/privacy-and-safety.md](docs/privacy-and-safety.md).
